┃ 板块：计算机系统
┗━━━━━━━━━━━━━━━━━━━━━━

💡 通俗理解
想象你去图书馆借书：你告诉管理员“我要借《数据科学入门》”（请求），管理员找到书递给你（响应）。RESTful API 就像图书馆的借书规则——你不需要知道书在哪个书架、怎么分类，只要按规则说“书名”和“操作”（借/还），管理员就能帮你搞定。它让不同系统（比如你的电脑和服务器）用统一、简单的方式“对话”。

🧠 核心要点
1. 资源是核心：每个东西（如用户、订单、数据集）都是一个“资源”，用URL（网址）唯一标识，比如 `/users/123` 代表用户123。
2. 动作用HTTP动词：GET（获取数据）、POST（创建新数据）、PUT（更新数据）、DELETE（删除数据），就像借书、还书、预约等操作。
3. 无状态：每次请求都独立，服务器不记住你之前做了什么——就像每次借书都要重新说“我要借书”，而不是指望管理员记得你上次借过。
4. 返回标准格式：通常返回JSON（一种键值对格式），比如 `{“name”: “Alice”, “age”: 30}`，方便程序直接读取。

📊 数据科学中的应用
当你从Kaggle下载数据集、调用Twitter API抓取推文、或使用Google Maps API获取地理数据时，背后都是RESTful API在工作。你只需发送GET请求，就能拿到结构化数据（JSON），直接用于分析或建模。

🔖 一句话记住
RESTful API 是系统间的“点餐规则”——你说“我要一份数据”，它按标准格式给你端上来。
