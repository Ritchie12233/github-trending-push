💡 通俗理解
把 API 想象成餐厅点餐：菜单上的每道菜（资源）都有固定名字，你只能用"看菜单、下单、改单、取消"这几种标准动作，不能闯进厨房自己炒。RESTful 就是这套"标准点餐规矩"。

🧠 核心要点
- **一切皆资源**：数据（用户、订单、模型结果）都当成"名词"，用 URL 定位，如 `/students/123`。
- **动词用 HTTP 方法**：GET 查、POST 增、PUT 改、DELETE 删——动作不写进 URL，靠方法表达。
- **无状态**：每次请求自带全部信息，服务器不记得你上次来过，像每次点餐都重新报一遍桌号。
- **统一接口 + 标准状态码**：200 成功、404 找不到、500 服务器出错，大家用同一套"暗号"沟通。

📊 数据科学中的应用
你训练好的模型要给别人用，通常包成一个 RESTful API：别人 POST 一条数据，你返回预测结果。调外部数据（如天气、股价）也是通过它。

🔖 一句话记住
**URL 说"要什么"，HTTP 方法说"干什么"，状态码说"成没成"。**
